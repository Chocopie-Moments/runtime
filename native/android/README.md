# Android development host

Unreleased. Android API 36 ARM64 emulator execution passed for standalone Kotlin, bare React Native and the exact Expo profile below; physical-device and minimum-API acceptance remain open. `ChocoView` is a thin main-thread Android host over the same Rust/ThorVG engine as iOS and WASM. Frames copy premultiplied RGBA into an Android bitmap; motion and admission remain in Rust. The caller must call `unload()` when permanently releasing a native view. Detach pauses scheduling without discarding player state. Hosts set `applicationActive` and `playbackEnabled` for their lifecycle and mounted offscreen content.

Build with an installed Android NDK, Meson, Ninja and Rust Android target:

```
ANDROID_NDK_HOME=/path/to/ndk bash scripts/choco/build-android-package.sh
```

The default ABI is arm64-v8a, Android API 24, and two build jobs. `CHOCO_ANDROID_ABIS='arm64-v8a x86_64'` includes the Intel emulator ABI. The script stages the JNI library and Kotlin native host inside the React Native package, which is then independently packable. No Android build downloads a runtime or executes authored asset code. `bundle://name.choco` resolves an application asset; Metro release resources, `asset:/`, file and HTTPS sources are bounded to 2 MiB. Debug builds permit local Metro HTTP. INTERNET permission belongs to the consumer if it uses remote assets; bundled assets need no network permission.

Real validation must cover Release Fabric loading from a packed package, bundled/offline assets, independent players, resize, state/trigger/seek/look/palette commands, invalid replacement and malformed files, mounted/offscreen and activity lifecycle, destruction, and native/WASM pixel equality. Emulator results do not establish physical-device performance or minimum-OS support.

The independent development Kotlin SDK is `native/android/sdk`, an Android library with no React Native plugin or dependency. After staging verified JNI slices with the command above, run `bash scripts/choco/build-android-sdk.sh`. It verifies the native source/library/notice hashes, packages canonical `ChocoView` and `ChocoNative`, and writes the AAR plus digest receipt under `release/android-sdk`. AGP 9.2.1, Kotlin 2.2.0 and Gradle 9.4.1 match the native consumer toolchain. CI compiles the independent AAR before installing React Native consumer dependencies. The standalone AAR and an additional R8-minified React Native Release APK compiled in private CI run 37754056317 (source d495713). The subsequent final AAR consumer executed through the public API with no React Native dependency, and earlier minified RN APK playback passed the native Activity and all eight Fabric checks. No Maven publication is configured.

Both Android libraries carry consumer R8 rules preserving the JNI class and methods. CI also builds a separate minified Release APK with `-PenableProguardInReleaseBuilds=true`; R8-minified RN execution and the minified standalone AAR consumer passed on the API 36 ARM64 emulator. For a standalone application, place the reviewed AAR in `app/libs`, add `implementation files('libs/choco-android-sdk-release.aar')`, and use `com.chocopie.ChocoView` on the main thread. Load bundled bytes through `load(bytes)`, set activity/playback state for your lifecycle, and call `unload()` when permanently disposing the view. Asset and networking policies belong to the host app.

`bash scripts/choco/build-android-aar-consumer.sh` builds the minified Kotlin-only proof application from the staged AAR, using the canonical verification Activity and public ChocoView API. There is no source/project or React Native dependency. CI uploads its APK and `AAR-CONSUMER.json` beside the SDK. Install that APK on a device, then run `CHOCO_ANDROID_APPLICATION_ID=com.chocopie.aarproof bash scripts/choco/run-android-verification.sh /new/evidence/directory` to exercise controls, independent players, scheduling, invalid inputs, disposal and save exact pixels. Compilation alone does not mark execution verified.
