# Choco compiled format

Status: development format **0, revision 2, semantics 1**. This is the implemented contract under conformance testing, not a released v1 or a platform-support promise. Format 0 revision 0 contained SVG; that representation is replaced, without a compatibility reader. Revision 1 also accepted retired authored track programs; revision 2 removes that branch, without a compatibility reader. Freeze v1 only after the gates in [the delivery plan](releasing.md) pass.

## Container and identity

`kind` is a nonempty descriptive category of at most 80 UTF-16 code units. It does not select renderer behavior or constrain app-state names. Product category lists are not part of decoder admission.

A `.choco` file is a ZIP32 archive with exactly these entries:

| Entry | Required | Contents |
| --- | --- | --- |
| `manifest.json` | Yes | Identity, palette, versions, controls, capabilities, hashes |
| `scene.json` | Yes | Compiled path geometry and explicit motion bindings |
| `motion.json` | Yes | Rig and one declarative motion program |
| `ATTRIBUTION.txt` | No | UTF-8 attribution, at most 16,384 bytes |

Compressed files are at most 1,048,576 bytes. Expanded entries together are at most 2,097,152 bytes. Readers never extract an archive into the filesystem. Entry names are case-sensitive and have no directory component. Duplicate names, unknown entries, encryption, descriptors, ZIP64, extra fields, comments, multiple disks, gaps, overlapping local records, mismatched local/directory sizes or CRCs, and bytes after the end record are errors. Compression methods are stored (0) or raw DEFLATE (8); flags are 0 or UTF-8 (0x800). A stream must terminate, consume exactly its declared compressed length and produce exactly its declared expanded length. Both readers reject trailing or concatenated DEFLATE streams, truncated streams and invalid stored-block length complements. Web inflation uses the public streaming interface of pinned pako 2.2.0, with bounded output chunks and a final-byte end-of-stream check; encoding remains fflate 0.8.3.

The encoder sorts entry names, fixes the DOS timestamp to 1980-01-01 00:00:00, and uses fflate 0.8.3 level 6. It writes UTF-8 JSON without whitespace, recursively sorts object keys in ECMAScript string order, preserves array order and uses `JSON.stringify` numeric spelling. JSON must contain finite numbers, have no duplicate object keys (including differently escaped spellings of the same key), and have at most 96 nested object/array containers. JSON is UTF-8 without a byte-order mark. Strings, including escaped strings and object keys, must represent Unicode scalar values: paired surrogate escapes are valid, unpaired surrogates are errors. Attribution text may begin with U+FEFF, which is preserved. Decoder acceptance does not require canonical key or number spelling; re-encoding produces the canonical spelling.

Each non-manifest entry has an exact byte length and lowercase SHA-256 in the manifest. Validate hashes before interpreting data. SHA-256 provides content integrity, not publisher authentication. The whole-file digest belongs in an external install receipt or release catalog, avoiding a circular hash. Private prompts, account data, installation credentials, host code, scripts, URLs, fonts and SVG source are not fields in this format.

A loader accepts an exact format/revision/semantics tuple. It must reject unsupported required capabilities and inconsistent declarations before mounting anything. Every capability is currently version 1. Requirements are derived from compiled scene/program contents; a manifest cannot hide an unsupported feature by omitting its name. The state list is sorted and exact: `idle`, app states, and nonempty `enter`/`hover`/`click` controls. App states cannot use those four reserved score-control names.

The schemas are generated by `scripts/choco/write-spec.ts` from `src/codec/schema.ts`:

- [Manifest schema](spec/choco-manifest.schema.json)
- [Scene schema](spec/choco-scene.schema.json)
- [Motion schema](spec/choco-motion.schema.json)

All objects reject unknown fields. The schemas describe local structure; graph, cumulative-resource and semantic checks below are also mandatory. Display-name limits count UTF-16 code units, as in the authoring contract; this is an additional restriction beyond JSON Schema's Unicode-character length. The runtime uses generated fixed validators rather than shipping the schema-construction library. Regenerate schemas and validators together. Package builds run `write-spec.ts --check` and fail if either is stale.

## Scene semantics

The viewBox is `[x, y, width, height]`; width and height are positive. Hosts preserve aspect ratio, center the drawing and clip presentation to the host viewport. Nodes are painted in order: their own shape, then children in array order. Each node carries a six-number affine matrix `[a,b,c,d,e,f]`, group opacity, subtree display flag and shape visibility. For column-vector points, `x'=a*x+c*y+e`, `y'=b*x+d*y+f`; world transforms multiply parent by local. Group opacity composites the group's rendered result once, not each child separately.

Contours start at an explicit point and contain line or cubic Bézier segments. Lines use `to`; cubics use `c1`, `c2`, `to`. `closed` joins the endpoint to the start. Open paths can have fill area; the compiler represents an SVG line with no fill. Shape fill uses nonzero or even-odd winding. Stroke width, caps, joins, miter limit and dash phase are explicit. No host SVG parser or font shaper is required.

Paint is none, RGBA color, linear gradient or radial gradient. Color channels and stop offsets are in `[0,1]`. A palette role replaces the RGB channels while retaining authored alpha. Palette roles are exactly `accent`, `secondary`, `ink`, `background`, each a six-digit hex color. Gradients have explicit user-space transforms, ordered stops and `pad`, `repeat` or `reflect` spread. Linear values are `[x1,y1,x2,y2]`; radial values are `[cx,cy,r,fx,fy]` with positive radius. Object-bounding-box paints are resolved by the compiler, before distribution.

A clip is a static scene tree in the clipped node's coordinate system. Its white filled geometry forms an alpha mask; clipping multiplies coverage and cannot introduce color. Clip winding and nested clips are retained. Clip nodes have no motion bindings. The shared ThorVG renderer uses retained alpha masks on native platforms and in WebAssembly. Browser hosts present the resulting pixels on canvas. Raster antialiasing is tested separately from geometry and motion.

Text is shaped and outlined during compilation. Reused geometry is expanded then. Generated glyphs and reused definition contents do not acquire new animation handles. The original named group and each originally addressable direct child retain explicit bindings. A node can carry its own part handle and an enclosing group's child alias; both transforms apply. Renderers must use the stored bindings rather than infer handles from expanded child positions.

The rig provides named-part bounds in viewBox coordinates, drawn-parent relationships and original child bounds. Default pivots use those bounds. It is produced with tight curve bounds, not the former approximate server rig. Text uses outlined glyph geometry. Scene and rig dimensions agree, handles are unique, every rig handle has exactly one scene binding, and named parts have matching named bindings. Carrier/attachment graphs must be acyclic and references must resolve.

The private product owns font selection, shaping and outlining. Installed runtimes consume only compiled glyph geometry and do not select system fonts. The product acceptance suite checks that browser and server compilation produce identical bytes for its text fixture; that sampled check does not certify every font or script.

## Motion semantics

A motion program has `kind: "score"`, a rig and the complete score, including ambient motion, follow, reactions, state transitions, gaze, visibility, attachments, pivots, strength and speed. An explicit empty score is valid static artwork. Compilation rejects scoreless authoring documents instead of dropping their old animation or inventing a score.

**Decision, 2026-10-08:** retire pre-score `states/tracks` artwork before launch. Do not implement its playback in Rust or maintain a browser compatibility path in `.choco`. Keyframes compiled from scores remain part of the current engine; they are not the retired authoring format. Authoring input requires scores; retired track programs are rejected rather than backported.

The motion schema fixes parameter bounds and enum values. Missing optional values take the semantic defaults in the motion owner. Unknown operations and unknown targets are errors even in inactive states. A tiny positive spring period is not a valid shortcut: follow periods range from 0.2 through 10 seconds. Scores are validated before spring integration or key compilation.

Semantics 1 preserves the behavior established during browser conformance. `native/choco-core` now owns that behavior for native and WebAssembly playback; host adapters forward controls and lifecycle events. Observable requirements include:

- Independent ambient, state, reaction, follow and gaze layers compose in the documented wrapper order. Updates that repeat the current state are no-ops unless restart is requested.
- State interruptions begin from the displayed pose and retain applicable held state. Going idle hands motion back to the base scene. Sequential reactions interrupt the reaction layer.
- Ambient cycles use the 12-second loop window and defined easing/key thinning. Key opacity is clamped before interpolation. Matrix interpolation across interruption bridges follows the sampled browser behavior.
- A virtual clock advances only through explicit seek. Pausing preserves clock phase; background time is not added on resume. Invalid/nonfinite clock inputs and addition overflow are errors.
- Reduced motion settles primary state changes without ambient or secondary follow motion. Gaze returns smoothly to its resting offset and carries the displayed offset when interrupted.
- Particle generation is seeded; flow and draw progress have deterministic effect states. Compiling those states without rendering their output is insufficient. Native renders seeded bursts, draw-on/off and flow copies. Rendering support does not by itself certify all capability interactions.

Draw-on/off changes only strokes, including inherited strokes and descendants of the target part; fills and clipping geometry remain unchanged. Each shape uses its own total contour length, including closing segments. Progress follows `cubic-bezier(0.65, 0, 0.35, 1)`, with backwards/forwards fill, score speed and explicit delay. Later-created effects replace earlier ones on the same stroke; cancelling one reveals the next active effect or restores authored dashes. Reduced motion omits these secondary effects. Zero-length paths retain their authored stroke/cap behavior.

The portable numeric corpus covers compiler outputs; actual browser/native event histories and effects remain additional release gates. This development specification does not claim that mathematical compiler agreement proves displayed-frame agreement.

Flow copies use the authored resting subtree, preserving paint, clipping and initially hidden descendants. They exclude descendant animation wrappers, gaze, generated effects and stroke-reveal animation; they never become motion targets. Copies sit immediately after the source inside its own motion/visibility wrappers, so the source and its ancestors carry the whole flight. Newer copies paint below older copies at the same source. Palette changes apply to source and copies together. Playback interpolates 31 prepared keys, including the browser's decimal serialization (translation 2 digits, rotation 3, scale 4), delay, stagger, score speed and opacity envelope. Reduced motion omits copies. Cancelling either active sequence group removes its flights; a virtual seek can rewind a completed, uncancelled flight.

The runtime reserves a bounded copy pool at mount: per target, the largest trigger count plus the largest state count, summed across targets. Extra retained geometry may contain at most 10,000 paints (including holders/anchors), 200,000 segments/contour starts and 8,192 gradient stops. Both decoders and the authoring compiler enforce this budget, including inactive states. Budget arithmetic uses wide integers in native code. This conservative pool trades bounded load-time memory for no geometry allocation during triggers or frames; bytes, base scene limits and pixel-surface limits still apply separately.

## Resource and host boundary

| Resource | Limit |
| --- | --- |
| Scene nodes, including masks | 10,000 |
| Scene node depth, root at zero | 32 |
| Contours / segments, each cumulative | 200,000 |
| Named rig parts | 100 |
| Child boxes per named part | 1,800 |
| Total named and child handles | 2,048 |
| Gradient stops per paint / cumulative | 256 / 8,192 |
| Dash lengths per shape | 256 |
| Public states including controls | 256 |
| Capabilities | 128 |
| Local coordinates and matrix coefficients | absolute value ≤ 1,000,000 |
| Composed matrix coefficients | absolute value ≤ 1,000,000,000 |
| Animated-parent determinant | absolute value ≥ 1e-12 |
| Native surface dimensions | 1–4,096 per axis; ≤ 4,194,304 pixels |

All geometry, colors, motion and matrices are finite. Negative widths/radii, out-of-order gradient stops, all-zero nonempty dash patterns and unresolved/duplicate bindings fail admission. Optional fields may be absent; explicit null is accepted only where the schema says nullable. A decoder must check cumulative limits, not only each collection separately.

Native stroke measurement is bounded to two million cubic subdivision visits per scene, depth 20, and total length at most 1e9 per affected shape. Nonconvergence or exhaustion fails renderer creation explicitly. Measurement runs only for shapes targeted by draw effects and never per frame; these backend execution limits do not change archive decoding rules.

The development C ABI accepts `.choco` bytes, returns errors before exposing a player, and lends a premultiplied RGBA pixel buffer until the next call on that handle. Hosts copy changed pixels before asynchronous composition and may retain their previous image when the returned `changed` flag is false. Viewport fitting checks finite coefficients within the 1e9 renderer limit before mutating pixels or calling the C backend; an inadmissible resize preserves the previous frame. Handles stay on their creating rendering thread and are destroyed exactly once. Concurrent live canvases currently share one rendering thread because the pinned renderer's memory pool uses thread-local state with global teardown. This is an explicit current backend constraint, not a cross-thread safety guarantee. Rust panic containment does not catch invalid caller pointers or C++ memory faults. Fuzzing, sanitizer checks and symbol isolation are still release requirements.

## Executable gates

`npm test` recompiles the synthetic capability corpus, checks canonical archive bytes and required-capability rejection, and exercises valid/malformed archive admission. `scripts/check-admission.mjs` gives the same frozen inputs to the native decoder. Regenerate the published schemas and validators together with `scripts/choco/write-spec.ts`; its `--check` mode rejects drift.

Build native `frames` and the WASM artifact, then run `node scripts/choco/verify-web.mjs fixtures/manifest.json`. It compares exact premultiplied RGBA bytes for identical state/input histories, retaining hashes and failed frames. The initial public corpus has 54 synthetic assets and 1,770 sampled frames. The private product additionally checks real customer-authorized artwork; that artwork is not redistributed here.

Release remains gated on capability/history and boundary checks, browser and packaged iOS/Android lifecycle checks, and physical-device startup/frame/memory/energy acceptance. The founder accepted the current browser bundle size for the first cutover and deferred desktop adapters and further size optimization. Identical sampled engine pixels do not prove correct browser composition or OS lifecycle handling. See `release-gates.json` for unfinished release work.
